02이 시트의 성격: 밀린 일 목록이 아닙니다

아님일이 얼마나 쌓였는지 보는 현황판이 아닙니다.
맞음정상적으로 처리되고 있다면 여기 없어야 하는 건들만 올라옵니다. 리스트에 있다는 것 자체가 "이 건은 확인이 필요하다"는 신호입니다.
원칙리스트에 없으면 정상 진행 중입니다. 목록에서 사라진 건 없어진 게 아니라 다음 단계의 기준으로 다시 감시됩니다.(케이스 흐름도)

03기초: 청구건은 이 순서로 흘러갑니다

청구건 하나(병약국 단위)는 아래 상태를 순서대로 지나갑니다. 각 상태에서 누가 움직여야 다음으로 넘어가는지가 핵심입니다.

상태무슨 단계인가다음으로 넘기는 사람
신청확인중신분증 검수 단계 정상 건은 당일 통과합니다신분증검수 매니저 (재요청 건은 고객)
대리인미지정병약국에 방문할 대리인을 아직 정하지 않은 상태센터 배당 담당자
대리인지정대리인은 정해졌지만 위임장출력을 하지않은 상태 위임장출력을 해줘야 발급매니저가 출력된 서류를 들고 활동이 가능합니다.센터 배당 담당자(위임장출력 처리)
위임장출력발급 진행 중) 대리인 활동 → 서류 도착 → 검수(*광역시 센터는 1차검수 후 서울검수센터로 발송 이후 서울검수매니저가 서류등록)발급매니저 → 검수 매니저

06정체구분 라벨: 왜 올라왔는지 한눈에

한 건에 여러 판정이 겹치면 쉼표로 함께 표시됩니다. 순서는 항상 같아서(만료 → 재배당 → 자동청구실패 → 세부단계 → 누락의심 → 체류) 필터를 걸어도 값이 흩어지지 않습니다.

라벨의미판정 기준
만료지남서비스기간(신청일+90일)이 끝난 건입니다신청경과일 91 이상
만료임박만료까지 15일 이하 남은 건입니다신청경과일 75~90
재배당정체정체 대상 중 재배당이 진행 중인 건입니다메모(폴리스·수기)에 '재배당' 언급 + 현재상태가 대리인미지정~위임장출력 → 재배당 탭으로 이동
자동청구실패정상 발급·검수를 거쳐 서류등록된 건이 자동청구 발송에 실패하여 수동 발송 대상이 된 건입니다자동청구 발송 실패 이력 존재 '보험사청구 → 전송내역 → 실패건만보기'목록과 동일 합니다.
발급도착정체(위임장출력) 활동은 시작했는데 서류가 오지 않은 건입니다활동일 있음 + 서류도착일 공란
검수정체(위임장출력) 서류는 도착했는데 검수가 안 끝난 건입니다서류도착일 있음
누락의심같은 배당의 다른 건들 일부분이 서류등록/청구서발송이 진행된건이 있는경우, 검수누락 가능성이 높은 건입니다배당 안에 서류등록/청구서발송까지 간 건 존재
체류정체상태별 체류 기준(05)을 넘겨서 올라온 건입니다체류경과일 ≥ 상태별 기준

07처리방법: 문구별로 이렇게 하면 됩니다

처리요청이렇게 하세요
미배당 지연건 확인필요① 병약국서비스불가사유·병약국메모부터 확인: 폐업·발급거부·비용발생 등 서비스불가면 서류발급실패 처리
② 서비스 가능하고 발급을 받아올 수 있다면 대리인 지정 (병약국 단위: 지정하면 그 병약국의 건들이 한꺼번에 풀립니다)
③ 발급이 불가능하면 기간만료 처리 검토
발급활동지연 확인필요대리인지정 건: 발급 가능한 상황인지 확인하고 위임장출력을 처리하세요(출력이 돼야 대리인이 활동을 시작할 수 있습니다)
위임장출력 건: ① 대리인이 아직 활동 중인지 (진행 중이면 진행 독려) ② 활동이 끝났다면 서류가 이미 도착했는데 서류도착일 입력이 누락된 건 아닌지 확인 누락이면 도착일 입력(실측상 가장 흔한 원인) ③ 병약국 발급 제약(병약국메모의 발급시간·휴무)으로 늦어지는지 확인하세요
공통: 만료지남이 붙어 있고 살릴 수 없다면 기간만료 처리
검수 진행상황 확인필요광역시 센터 건은 서울 검수센터 발송 여부부터 확인 → 발송됐으면 검수가 왜 안 끝났는지 확인하세요
검수누락 확인필요같은 배당의 나머지는 끝났고 이 건만 빠진 상태 → 우선 확인해서 검수를 마무리하세요 (우선순위 가장 높음)
청구서 발송 처리발급·검수가 끝난 건 → 자동청구 실패 건도 포함돼 있으니 보험사청구(청구서 발송)를 처리하세요 (만료지남이 붙어 있어도 발송하면 됩니다)
기간만료 처리는 어디까지? 기간만료 처리는 대리인이 활동을 시작하기 전 단계(미지정·지정)에서만 검토합니다. 활동이 시작된 건(위임장출력·서류등록)은 이미 들어간 일이 있으니, 만료를 넘겼어도 살리는 쪽을 먼저 봅니다.

10화면 규칙

행 색상구간행 배경이 흰색/연파랑으로 번갈아 칠해집니다 — 색이 바뀌는 지점이 배당이 바뀌는 지점. 같은 색으로 이어진 행들 = 같은 배당의 청구건(미배당 건은 같은 병약국끼리)이고, 한 색 덩어리를 하나의 처리 단위로 보면 됩니다.
정렬가장 오래된 신청이 있는 묶음이 위로 옵니다. 배당 있는 건이 먼저, 미배당(대리인미지정)은 아래 블록입니다.
갱신매일 시트 전체를 새로 그립니다. 수기메모 외의 직접 수정·서식은 다음 날 사라집니다.

11관제 밖 영역 — 일부러 안 올리는 것

서류등록의 일반 팩스·이메일 대기 건(자동청구 이력 없음)은 이 리스트에 올리지 않습니다. 보험사별 하루 발송한도 때문에 줄 서서 기다리는 정상 대기가 대부분이라, 올리면 "확인이 필요한 예외"와 "그냥 기다리는 중"이 섞여버리기 때문입니다. 이 영역은 발송 시스템과 청구팀 큐가 관리합니다.

사각지대 감시 다만 이 대기 덩어리가 비정상적으로 커지는지는 봐야 하므로, 개편 때 요약 탭에 집계 한 줄(건수·최장 대기·보험사별)을 추가할 예정입니다.

12기준의 근거 — 왜 이 숫자인가

실무에 꼭 필요하진 않지만, "왜 15영업일이야?"가 궁금할 때 읽는 섹션입니다.

대리인지정 15영업일

과거 데이터에서 대리인지정 → 다음 상태로 넘어가는 데 걸린 시간의 상위 99%가 약 8영업일 안에 끝났습니다. 15영업일은 "정상 운영으로는 설명이 안 되는" 확실한 선이고, 실측에서 10~20영업일 구간이 비어 있어(정상군과 이상군이 이미 갈라져 있음) 애매한 경계가 없었습니다.

서류등록 15영업일 + 등기·자동청구실패만

서류등록에 10~14영업일 머문 건들(약 1만 건)은 물량이 가장 큰 보험사 두 곳이 79%를 차지하는 하루 발송한도 대기였습니다. 15영업일이 분포가 꺾이는 지점이라고 판단 정체 리스트의 서류등록 절반가량은 자동청구 실패 후 수동 전환된 건입니다.

대리인미지정 — 왜 체류가 아니라 신청경과일인가

미지정 풀의 다수는 신청 30일 이내 신규 건이라, 체류 기준으로 자르면 수천 건이 걸립니다. 실제 위험은 "만료가 다가오는데 지정이 안 된 것"이므로 만료 15일 전(75일)을 기준으로 잡았고, 지정이 병약국 단위 작업임을 이용해 병약국으로 묶어 봅니다.

지금 만료지남이 많은 이유

5월에 대량 유입된 물량의 꼬리가 8월부터 만료선(신청+90일)을 넘고 있습니다. 이 물량이 소화될 때까지 만료지남 건은 당분간 늘어나며, 현재 리스트의 가장 큰 덩어리입니다.

13종결·재배당 탭

재배당 탭

메모(폴리스·수기)에 '재배당'이 적혀 있고 현재상태가 대리인미지정~위임장출력인 건은 센터 리스트에서 빼고 재배당 탭에서만 추적합니다 — 수기메모에 쓰면 다음 날부터 이동합니다. 재배당 중에도 정체기간·신청경과일은 계속 누적됩니다 (시계가 멈추지 않습니다).

성공서류등록에 도달하면 재배당 성공 → 탭에서 빠집니다. 이후엔 메모에 '재배당'이 남아 있어도 재배당으로 보지 않으니 메모를 지울 필요가 없습니다.
이탈실패·취소로 끝나면 종결 탭으로 갑니다.
화면센터 블록 순 정렬, 신청경과일로 만료 위험을 함께 봅니다.

종결 탭

정체 목록을 벗어나 끝난 건의 기록입니다. 시간 컬럼이 세 가지인 것만 기억하면 됩니다.

컬럼재는 구간답하는 질문
소요일신청일 → 종결일 (달력일)전체 며칠 걸렸나, 만료 전에 끝났나
정체기간(영업일)정체 목록 등재 → 종결일문제로 잡힌 후 며칠 만에 처리됐나
정체구분종결 당시 마지막 판정어떤 정체였다가 끝났나
현재상태지금 실제 DB 상태정말 끝났나 — 청구서발송이면 완료, 서류등록이면 아직 발송 대기

종결사유는 "당시 기록"이고 현재상태는 "지금 사실"입니다. 현재상태가 터미널(청구서발송· 서류발급실패·취소·반송)이 아닌 건은 종결 기록만 있고 실제로는 진행 중인 건입니다 — 대부분은 서류등록(발송 대기)이고, 드물게 재검수 등으로 되돌아간 건도 있습니다. 이런 건이 해당 상태의 정체 기준을 넘기면 리스트에 다시 나타나고, 그때 종결 탭에서는 빠집니다 — 사라진 게 아니라 계속 감시되고 있다는 뜻입니다.

종결 기준 개편 예정 지금 종결 탭은 "서류등록/서류발급실패 도달"을 종결로 봅니다(위임장출력만 관제하던 시절 기준). 상태별 관제에서는 서류등록도 관제 단계이므로, 개편 때 종결 = 청구서발송(정상) 또는 실패·취소·반송(이탈) 도달로 바뀝니다. 기간만료 처리 실적도 그때부터 실패사유=기간만료로 집계됩니다.

14용어집

체류 / 체류경과일 / 체류시작일
측정 단어입니다. 현재 상태에 들어온 날(체류시작일)부터 지난 영업일이 체류경과일. 같은 상태 재진입 시 마지막 진입 기준.
정체
판정 단어입니다. 체류·만료 기준을 넘어 "정상이 아니다"라고 판정된 상태. 측정(체류)과 판정(정체)을 구분해 씁니다.
만료임박 / 만료지남
신청경과일 75~90 / 91 이상. 서비스기간은 신청일+90일까지(90일째 = 마지막 유효일).
배당번호 (A00000000) / 병원별번호 (M00000000)
배당 = 병약국+대리인 묶음 작업 단위 / 병원별번호 = 청구건 식별자(행의 키).
하이웹넷
보험사 전자청구망. 자동청구 시도 후 실패하면 수동 흐름으로 복귀 → 라벨 "자동청구실패".
폴리스메모 / 수기메모
폴리스메모 = 시스템의 청구건 메모(읽기 전용) / 수기메모 = 시트에서 직접 쓰는 열(노란 배경, 매일 갱신에도 보존 — 종결·재배당 탭 이동 시에도 유지).
2h센터
여러 지역의 청구건을 대신 발급하는 별도 인력 그룹. 지리 센터와 무관하게 "2h센터"로 분류.
누락의심
같은 배당의 형제건들은 검수완료됐는데 이 건만 검수 단계에 남은 것 — 잊힌 건일 가능성이 높아 우선 확인.
센터별 정체 현황 온보딩 · 기준이 바뀌면 이 문서도 함께 갱신됩니다.
